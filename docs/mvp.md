# RMail MVP

## Цель

RMail — быстрый desktop-клиент для личной и рабочей почты. Первая версия должна позволять безопасно подключить IMAP/SMTP-ящик и ежедневно разбирать почту без лишнего интерфейсного шума.

## Пользователи и сценарии

1. Пользователь добавляет аккаунт вручную: IMAP/SMTP-хост, порт, TLS и учётные данные.
2. Пользователь читает входящие, переходит по тредам и работает с папками.
3. Пользователь быстро архивирует, удаляет, помечает и отвечает на письмо.
4. Пользователь создаёт письмо, прикладывает файлы и отправляет его через SMTP.
5. Пользователь ищет уже синхронизированное письмо, в том числе без сети.

## В границах MVP

- Один или несколько IMAP/SMTP-аккаунтов.
- Входящие, отправленные, черновики, корзина и пользовательские папки.
- Локальный кеш писем и поиск по кешу.
- Треды, чтение HTML- и plain-text-писем, вложения.
- Создание, сохранение черновика и отправка письма.
- Архивация, удаление, отметка прочитанным и флагирование.
- Светлая и тёмная темы, клавиатурная навигация и desktop-уведомления.

## Вне MVP

- OAuth-подключения для конкретных провайдеров.
- Календарь, контакты, правила и серверные фильтры.
- PGP/S/MIME, snooze, scheduled send и AI-функции.
- Mobile-версии и командная совместная работа.

## UX-принципы

- Трёхпанельный layout: навигация, список писем, содержимое треда.
- Список писем доступен сразу из кеша; синхронизация не блокирует работу.
- Главные действия имеют горячие клавиши и отменяемы, где это возможно.
- Не показывать внешние изображения до явного разрешения пользователя.
- Состояния загрузки, ошибки и офлайн-режим должны быть заметны, но не навязчивы.

## Технические решения

- Desktop shell: Tauri 2.
- Frontend: React, TypeScript, Vite.
- Компоненты: shadcn/ui и Tailwind CSS; почтовые сущности — собственные компоненты.
- Backend: Rust; коммуникация с UI только через узкие типизированные Tauri-команды.
- Секреты: Tauri Stronghold; учётные данные не хранятся в UI, логах или SQLite.
- Данные: локальная SQLite-база и фоновая синхронизация IMAP.
